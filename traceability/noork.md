# Traceability: Noor Al Kuwari (noork)

**Target feature:** Focus Session: a timed work/break session with a colored focus bar (green = active, yellow = idle 2 min or left opencode + "Need help?" check-in, red = check-in unanswered for 60 s). Main source files, all in `packages/app/src/pages/home/focus-session/`:

- `controller/session-controller.ts`: timer, work → break → next round, pause / resume / end
- `controller/idle-monitor.ts`: green → yellow → red status and the check-in
- `controller/focus-timeline.ts`: records the colored stretches of a round and lays them out as % widths
- `controller/focus-score.ts`: focus % and wiring of monitor → score → timeline (`followFocus`)
- `controller/presets.ts`: 25/5 and 50/10 presets, custom timing validation

**Property tests** (all in `packages/app/test/noork/`, one file per requirement):

- R1: [`r1-check-in.property.test.ts`](../packages/app/test/noork/r1-check-in.property.test.ts)
- R2: [`r2-kept-stretches.property.test.ts`](../packages/app/test/noork/r2-kept-stretches.property.test.ts)
- R4: [`r4-round-length.property.test.ts`](../packages/app/test/noork/r4-round-length.property.test.ts)
- R5: [`r5-pause.property.test.ts`](../packages/app/test/noork/r5-pause.property.test.ts)
- Generators (with an explanation of each): [`arbitraries.ts`](../packages/app/test/noork/arbitraries.ts). Harness that wires the real controller pieces on a fake clock: [`harness.ts`](../packages/app/test/noork/harness.ts)

Run locally: `cd packages/app && bun run test:properties` (also runs in CI as part of `bun turbo test` → `@opencode-ai/app#test`).

## Step 3: run, triage, fix

**Result:** all 14 properties pass against the current code. fast-check runs 100–300 generated inputs per property (about 29,000 `expect` checks in under 1 s). The properties found no code bugs.

| #   | What happened                                                                                                                                                                                                                                                                                                                                                                                                                            | Outcome                         | Fix                                                                                                                                                                                                                |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Before trusting the green run, I checked that the properties can fail (table below). An idle threshold of **2:01 instead of 2:00** in `idle-monitor.ts` was **not** caught. The R1 model and the boundary generators imported `IDLE_AFTER_MS` / `UNRESPONSIVE_AFTER_MS` from the code under test, so when the code's number was wrong, the "expected" number was wrong in the same way. After the fix, the 2:01 bug is caught by P1.1. |
| 2   | Typecheck under `noUncheckedIndexedAccess` flagged array indexing in the property files (e.g. `base.segments[i].width`).                                                                                                                                                                                                                                                                                                                 | **Wrong test** (test code only) | Used `?.` / `!` where the length was already asserted to match.                                                                                                                                                    |

### Making the properties show up in CI

`packages/app`'s `test:unit` script runs with `--only-failures`, so passing tests never appear in the CI log. The property tests live in `packages/app/test/noork/`, outside `src/`, and run in a new `test:properties` script without that flag, which the package's `test` script calls. `@opencode-ai/app#test` is already listed in `turbo.json`, so `bun turbo test` in `test.yml` runs it on every PR and prints one `(pass)` line per property.
